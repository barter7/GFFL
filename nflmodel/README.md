# nflmodel — NFL Player Props Model

The NFL sibling of **PropSZN** (the MLB pitcher-strikeout model). Same
architecture, four markets:

| Market | Shape | Model |
|---|---|---|
| Receptions | discrete count | team pass-volume dist × Beta(target share) × Log5 catch rate → Poisson mixture P(rec = n) |
| QB pass yards | continuous | volume dist × ratio-adjusted yards/target × Normal residual → P(yds > line) |
| QB pass TDs | discrete count | blended Vegas/volume λ → **empirical** TD-count shape (λ-bucketed, exponentially tilted) |
| Anytime TD | binary | Vegas-implied team TDs × usage-prior TD share → 1 − e^(−λ) |

Every market is the same recipe the strikeout model uses:
**matchup-adjusted rate × volume-distribution mixture**, with Vegas
game context (spread/total → implied team totals) playing the role
PropSZN's opponent-wOBA adjustment plays, and defense factors shrunk
empirical-Bayes style toward 1.0.

## Files

```
utils.R            pure helpers: odds conversion, Log5, shrinkage, Beta grids
pbp_data.R         play-by-play layer: refresh_pbp() / load_pbp_cache()
                   (nflfastR pbp, 372 cols/play, last + current season)
game_context.R     per-game context synced to pbp by game_id via
                   nflreadr::load_schedules(): closing spread/total/
                   moneylines + juice, rest, referee, head coaches,
                   starting QBs, stadium/roof/surface, parsed weather.
                   Optional data/context/coordinators.csv adds OCs
                   (no R-package source exists for coordinators)
nfl_features.R     feature layer (port of the owner's original prep
                   script): gamelogs + efficiency, WP-state playcalling,
                   defense-allowed tables + positional ranks, EPA ranks,
                   snap counts, NGS, unrealized air yards, spread-bucket
                   game scripts, play-volume projections. All builders
                   take (asof_season, asof_week) — no lookahead.
                   Optional PFF drop-in via data/pff/*.csv
roster_context.R   per-game depth charts + weekly injury reports
                   (Out/Doubtful/Questionable + practice status), both
                   vendor formats normalized to one per-game schema
data_sources.R     nflreadr -> data/cache/*.csv (model reads only the cache)
model_core.R       calibrated constants + all four market projections
calibrate.R        one-off: fits the constants hard-coded in model_core.R
backtest.R         walk-forward validation (no lookahead)
scrape_props.R     Action Network NFL props + odds-movement ledger
results_tracker.R  weekly snapshots, opening odds, matched results
run_model.R        weekly driver: data -> projections -> props -> card + report
report.Rmd         HTML weekly card
```

## Weekly usage (in season)

```bash
cd nflmodel
Rscript run_model.R            # upcoming week: card + report in data/results/
```

Requires R with dplyr/tidyr/readr/purrr/httr/jsonlite/lubridate, plus
`nflreadr` for data refresh (the model itself runs offline from the
cache). First-time setup: `install.packages(c("nflreadr", "rmarkdown"))`.

## Validation

Walk-forward backtest (fit strictly on data before each projected week;
constants calibrated on 2021–2024 only, 2024 used to tune two
post-calibration constants, 2025 untouched holdout):

```bash
Rscript backtest.R             # 2025 weeks 5-17
Rscript backtest.R 2024 5 17   # tuning year
```

2025 holdout results (n = 3,144 receptions / 393 QB games / 3,558
anytime-TD player-games):

- **Receptions** — MAE 1.32 vs 1.34 naive; P(over) calibration within
  ~2–3pp across all probability buckets
- **Pass yards** — MAE 61.2 vs 65.4 naive; PIT deciles near-uniform
- **Pass TDs** — mean 1.49 vs 1.40 actual (~1.5σ); P(2+) 0.445 vs
  0.425 (~0.8σ; 2024 missed 2.8pp the other direction)
- **Anytime TD** — Brier 0.154 vs 0.165 naive; calibrated within
  noise in every bucket except (0.4,0.5] running ~5pp hot

## Data

`data/cache/` is regenerated by `refresh_cache()` (nflreadr). The
backtest was developed against caches built from the nflverse
`games.csv` (schedules + Vegas lines) and weekly player logs; any
source matching the schema in `data_sources.R` works.

Known cache-source nuance: the model uses **team targets** as its pass
volume unit (not attempts) so that target shares, catch rates and
yards-per-target stay internally consistent across data sources.
